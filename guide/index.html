THE VERIFICATION TOOLS HANDBOOK

How to build
verification tools.

A step-by-step guide to turning questions, numbers, and dates into ready-to-copy text. Start with a simple form, then follow the actual Formatter and Calculator examples. No coding experience needed.

In this guide 1. Understand the pieces 2. Build your first tool 3. Put answers into text 4. Re-open request rules 5. Rental-history dates 6. Allowances & missing days 7. Add fields & show the sum 8. Salary & calculations 9. The 60-day boundary 10. Organize & share inputs 11. Test, save & keep work 12. Troubleshooting

1. Understand the pieces

A tool is a small form with instructions for what to write. You choose the questions, decide when particular wording should appear, and connect buttons to the finished text.

  1. 01 / CollectAsk for a name, date, number, or choice.
  2. 02 / DecideCheck a rule, such as “total months is at least 12.”
  3. 03 / WriteFill a template with those answers, then copy it.
Words you will see in the builder
WordWhat it means
InputA field someone fills in when using the tool.
LabelThe question or name shown above a field, such as “Move in date.”
Variable nameThe name the tool uses to find that field’s answer, such as move_in_date_input.
Generated textThe finished message. Its template can contain ordinary words and variables.
Condition / ruleAn instruction: “If this is true, use this text.” Rules are checked from top to bottom.
Default generated textThe text used when no rule matches. Give it useful wording so an unmatched case is understandable.
ContainerA group of related fields or buttons that can be arranged or shown together.
OffsetAn amount added to the value being compared against. With dates, this moves the comparison date forward or backward.

Use Text input for names or short answers, Number input for amounts, Date input for dates, and Radio button group when someone must choose one answer. Email and Phone inputs help format and check contact details.

Start here / Discontinue Request

2. Build your first tool

The existing Discontinue Request tool collects a name and phone number and puts them into one sentence. This simplified version is a good first project.

  1. Open Manage tools, choose a category, and select Create new tool. Give it a Tool name, such as “Discontinue request practice,” and choose its category.
  2. Add a Text input from the elements palette. Select it on the canvas. Set Label to “Name” and Variable name to name_input.
  3. Add a Phone input. Set its label to “Phone” and its variable name to phone_input.
  4. Add Generated text. Set Generated text ID to discontinue_note, then click Apply ID. This identifies the output that your buttons will use.
  5. In Default generated text, paste the example below. Leave Hide until generated enabled if you want the result to appear only after clicking Generate.
  6. Add a Generate button. Select it and enable discontinue_note under Linked generated text.
  7. Add a Copy button and choose discontinue_note under Copy from. Add a Reset button to clear the form for the next task.
  8. Click Save tool. Return to the workspace through Manage tools and Use tools. Enter sample details, click Generate, and review the result.
We received a request from the property staff ${name_input} using the phone number ${phone_input} requesting to discontinue the verification.

The canvas is for building and selecting elements. Test the working controls in the tool workspace after saving. If a saved tool is not on the category board, add it from Available tools in Manage tools and save the board changes.

Using the public demo? Save applies changes to the current demo session. Refreshing restores the published tools. See saving and keeping your work before leaving.

3. Put someone’s answer into your text

A variable is a reusable blank in a sentence. Select your Generated text element, place the cursor where the answer belongs, and use the variable insertion buttons. You can also type the variable between ${ and }.

Incoming call from ${name_input} using ${phone_input}.

Use the Variable name, not the visible label. Match its spelling and capitalization exactly. Names use letters, numbers, and underscores; each input needs a different name within its tool.

An ordinary variable inserts an answer. A formula does arithmetic: ${hourly_rate * hours_per_week} multiplies two numbers. A radio choice can be inserted as text, but it cannot be multiplied or added as a number.

A radio option has a label and a stored value. For example, the Formatter displays Rental but stores rental. Inserting that variable writes rental into the sentence.

Formatter / Re-open Request

4. Let one choice pick the wording and another fill it in

In the existing Formatter, re_open_request_radio_group_1 chooses the reason for reopening. A second group, re_open_request_radio_group_2, chooses Rental or Employment. The second choice becomes a word inside the sentence.

Select the Generated text with ID re_open_request_gen_id, click Add condition, and use these settings:

Re-open request: first rule
Condition sourceSingle variable
When variablere_open_request_radio_group_1
Comparisonis equal to
Selected optionInformation Available from Reference
Use this text when matchedUse the template below.
We received a request from the property staff ${name_input} using the phone number ${phone_input} to re-open the ${re_open_request_radio_group_2} verification.

Add a second rule with the same When variable, but choose Add Verification Comments as the Selected option. Its text can be:

${name_input} requested to re-open the ${re_open_request_radio_group_2} verification.

Test both reasons with both Rental and Employment. You do not need to make the second radio group the condition just to include its answer in the output.

First match wins. The app uses the first matching rule’s complete text. It does not join the text from every matching rule. Use Move earlier and Move later to set the order.

Calculator / RH Calculator

5. Check whether a stay reaches the required months

The existing Calculator uses these three inputs and the Generated text ID rh_calc_gen_text. “RH” means rental history.

For move-in July 25, 2022, 12 months gives a target of July 25, 2023. A move-out date of November 3, 2023 matches. Reversing the two date variables asks a different question and will not give this result.

Enter dates as MM/DD/YYYY. September 30, 2023 is 09/30/2023, not 30/09/2023. The calendar picker can help avoid confusion. Months are calendar months, not a fixed 30 days: January 31 plus one month becomes the last day of February.

Put an invalid-date rule first

Before the full-requirement rule, add a rule with When variable move_in_date_input, Comparison is greater than / after, Compare against Another variable, and Comparison date move_out_date_input. Choose Days and a fixed offset of 0; leave the additional offset blank. Use “Move-in date cannot be later than move-out date.”

This is a recommended correction to the saved example’s one-day offset. Zero catches a move-in date even one day after move-out.

6. Allow 15 days, but show the original shortfall

Keep the full-requirement rule above. Add another rule immediately after it, with the same settings except Additional offset (days) is -15. This moves the target date 15 days earlier.

In this allowance rule’s Use this text when matched, insert:

The required months would be met by adding ${date.remainingDaysBeforeAdjustment} days.

With move-in 10/10/2022 and move-out 09/30/2023, the result says 10 days. The additional adjustment affects whether the rule matches; this variable still counts to the original target.

Which remaining-days variable should I use?
VariableMeaning and example
${date.remainingDaysBeforeAdjustment}Days until the full target, before the extra day adjustment. Shows 10 in the example above.
${date.remainingDays}Days until the adjusted target, including the allowance. Shows 0 because September 30 is already past September 25.

Both counts stop at zero after their target is reached. They belong in a date rule’s matched text, not the default text or a radio/number rule.

Cover dates outside the allowance too

For a useful shortfall message, add a fourth rule. Use the allowance rule’s settings, including -15, but change Comparison to is less than / before. Write:

The stay is ${date.remainingDaysBeforeAdjustment} days short of the full requirement, and ${date.remainingDays} days short even with the allowance.

The recommended order is: invalid dates → full requirement → within allowance → outside allowance. This extends the existing Calculator’s three-rule example and avoids leaving unmatched dates with an empty result. Use a default such as “Review the entered dates.” as a final fallback.

Test with move-in 10/10/2022, 12 required months, and a -15-day allowance
Move-outExpected result
09/24/2023Outside allowance: 16 days short of the full target; 1 day short of the adjusted target.
09/25/2023Within allowance: 15 days short of the full target.
09/30/2023Within allowance: 10 days short of the full target.
10/10/2023Full requirement met. The earlier full-requirement rule wins.

The sign matters. -15 allows a stay to end earlier. 15 moves the target later and requires 15 extra days. The app adds months first, then applies the extra days.

Calculator / Multiple RH

7. Add as many address fields as needed and use their total

The existing Multiple RH example uses a repeatable Number input. Someone enters the months for the first address, then adds more fields for additional addresses. The same variable automatically becomes the sum of all entries.

  1. Add a Number input labelled “Required months.” Use variable name multiple_rh_required_number_input, Default value 12, Minimum number 0, and Step 1.
  2. Add a Number input labelled “Months stayed on address 1.” Use the existing example’s variable name months_stayed_number_on_address_input.
  3. Enable Allow additional fields. Set Add field button text to “Add another address.” Set Minimum number to 0 and Step to 1 for whole months, or a suitable decimal step if your workflow accepts fractions.
  4. Add or select Generated text with ID Multiple_RH_gen_text. Add the rule below, then link a Generate button to this output.
Check the combined rental history
Condition sourceSingle variable
When variablemonths_stayed_number_on_address_input
Comparisonis at least / on or after
Compare againstAnother variable
Comparison numbermultiple_rh_required_number_input
OffsetLeave blank or enter 0.

Use this matched text:

Verified correct: The required rental history has been met with a total of ${months_stayed_number_on_address_input} months verified.

Add a second rule with Comparison is less than / before and the same comparison number. Its text can be:

${months_stayed_number_on_address_input} months verified from the combined addresses - does not meet the required RH.
  1. Address 14 months
  2. Address 25 months
  3. Address 33 months

4 + 5 + 3 = 12. The variable inserts 12, and the first rule matches a required value of 12. You can also insert this variable directly into Default generated text; a condition is not required just to display the sum.

The tool begins with one field. Click Add another address twice to reach three fields. Labels ending in 1 become 2, 3, and so on. You can instead write Address {index}: months stayed to choose where the number appears.

Complete every added field or remove unused ones. Blank entries do not count as zero. Minimum, maximum, and step apply to each field individually. Reset removes added fields and restores the first field’s configured default, if any.

This feature adds the numbers entered. It does not inspect address dates or remove overlapping periods. Enter the month amounts you intend to count.

Calculator / Salary Calculator

8. Calculate amounts inside generated text

The Salary Calculator has two Number inputs: Hourly_Rate_input and Hours_per_Week_input. It uses formulas in the Default generated text of separate outputs.

Copy these salary templates
OutputTemplate
Weekly${Currency(Hourly_Rate_input * Hours_per_Week_input)}
Every two weeks${Currency((Hourly_Rate_input * Hours_per_Week_input) * 2)}
Annual${Currency((Hourly_Rate_input * Hours_per_Week_input) * 52)}
Monthly average${Currency(((Hourly_Rate_input * Hours_per_Week_input) * 52) / 12)}
Twice a month${Currency(((Hourly_Rate_input * Hours_per_Week_input) * 52) / 24)}

* means multiply, / means divide, and parentheses group the steps. Currency(...) displays the answer as US dollars with two decimal places. These examples assume the same weekly hours for 52 weeks; the monthly result is an average.

Test with an hourly rate of 20 and 40 hours per week: weekly $800.00, annual $41,600.00, and monthly average $3,466.67. A single Generate button can select all these outputs under Linked generated text.

Choose wording based on a calculation

If you have separate Number inputs for several amounts, choose Condition source → Calculation, then Operation → Sum. Select each input under Number 1, Number 2, and so on. Use Add number input for another amount. Choose your Comparison and Comparison number.

For example, if Income 1 and Income 2 total at least 5,000, use Total income: ${calc.result}. in that rule’s matched text. This special variable belongs to a Calculation rule. For a single repeatable input, use its own variable as explained in Multiple RH; it already provides the sum.

Sum adds; Difference subtracts later amounts from the first; Product multiplies; Quotient divides in order. Division by zero or missing values prevents generation until corrected.

Calculator / 60-day Lease Overlap Calculator

9. Decide what happens exactly at the boundary

The Calculator’s 60-day example compares lease_end_date_input with applications_start_date_input plus 60 days.

Choose Single variable, When variable lease_end_date_input, Compare against Another variable, and Comparison date applications_start_date_input. Set Offset unit to Days, Offset (days) source to Specific number of days, and Offset (days) to 60.

Choose the comparison that matches your intended wording
Intended thresholdComparison
60 days or moreis at least / on or after
More than 60 daysis greater than / after
Less than 60 daysis less than / before

The existing Calculator includes exactly 60 days in its “detected” result. The separate 60-Day Lease Overlap tool uses “greater than 60” and “less than 60,” leaving exactly 60 to its default text. When adapting that tool, choose which result should include equality or add an equality rule.

Test 59, 60, and 61 days. With application start January 1, 2023, these dates are March 1, March 2, and March 3. This guide explains how the configured comparison behaves; choose the threshold your workflow calls for.

10. Keep complex tools easy to use

Group related fields

Use a Container for each task or section. A column places items one below another; a row places them side by side. Keep labels descriptive, use spacing between sections, and check the layout at a narrow browser width.

The Formatter groups its Re-open Request, Release of Information, and other scenarios. The Calculator groups Salary Calculator, RH Calculator, 60-day Lease Overlap Calculator, and Multiple RH under a radio selection.

Show only the relevant section

Give the tool a Radio button group with an option for each section. Keep this group outside the containers it controls. Select a Container and set Container visibility to Show when selected, then choose its Visibility radio group and Visibility selected option. Put the related fields and controls inside it. A Generated text element also has Show when selected, Visibility radio group, and Visibility selected option settings.

Generated text with Show when selected updates immediately from the current answers. If you prefer a deliberate Generate step, leave it off and use Hide until generated with a linked Generate button. Showing a container controls its visibility; the Generated text’s own settings still determine when its result appears.

Share an answer between tools

Enable Global tool in the source tool’s settings to make its inputs available to other tools in the same category. Keep that source tool on the category board. In another tool, select its variable beginning with global., such as ${global.name_input}.

Give shared inputs unique variable names. Reset the source tool to reset those shared answers. Use local inputs when each tool should collect its own answer.

11. Test, save, and keep your work

Test each branch before using a tool for real work. A successful Save checks the configuration, but it cannot tell whether your wording and thresholds match what you intended.

  • Typical values: Does the expected rule produce the right sentence?
  • Exact boundaries: Test below, exactly at, and above the requirement.
  • Missing answers: Leave a needed input blank and confirm the tool asks for it.
  • Every choice: Try each radio option and check the visible fields and output.
  • Repeatable fields: Add, edit, and remove entries; verify the total and the generated wording.
  • Copy and Reset: Check that Copy targets the right result and Reset returns the form to its starting state. Number inputs restore configured defaults.

What Save keeps

Save tool keeps the tool design in the current environment: its fields, labels, rules, templates, and button links. It does not save the answers typed during use or the generated notes.

On the public demo, changes are temporary and disappear when the page refreshes. Click Download tool JSON in the editor to keep a copy of the tool definition, then give that file to the person maintaining your published workspace. A JSON file is a saved description of the tool, not a document containing completed verification notes. Correct any configuration errors first if the download button is unavailable.

In the local authoring version, Save writes the tool to the project’s catalog. Publishing those changes is a separate step for the site maintainer. Copy completed notes before resetting or leaving the workspace.

To keep this guide for later, use your browser’s Print → Save as PDF. The guide has a print layout and can be read without JavaScript.

12. Find the cause when a result looks wrong

The generated text is empty.

Check that Generate is linked to the right Generated text ID. Fill the inputs used by the rule or template. If no rule matches and Default generated text is blank, the result is blank. Add a useful default and check whether the output is inside a hidden container.

A date rule does not match even though the stay is long enough.

For a minimum stay, When variable is the move-out date; Comparison date is the move-in date. Add the required months to the move-in date. Check the date format, selected offset unit, and the order of rules. An earlier matching rule prevents later rules from being used.

The 15-day allowance makes the requirement harder to meet.

Use -15 for Additional offset (days). A positive 15 moves the comparison date later. Make sure the full-requirement rule is above the allowance rule.

I expected a 10-day shortfall, but the result says zero.

Insert ${date.remainingDaysBeforeAdjustment} inside the date rule’s matched text. ${date.remainingDays} includes the allowance, so it returns zero once the adjusted date has been reached.

A radio variable is reported as needing to be a Number input.

Insert the radio value by itself, for example ${re_open_request_radio_group_2}. Do not put it inside arithmetic or Currency. Numbered variable names are valid; the final _2 does not make a radio answer a number. Also confirm that the tool has that exact variable name.

How do I display the total of all additional fields?

Use the repeatable Number input’s existing variable, such as ${months_stayed_number_on_address_input}. It includes the first field and every added field. You do not need to create a separate total input or refer to each added row.

The wrong rule’s text appears.

Only the first matching rule supplies the result. Put the more specific rule first. For rental history, a fully completed stay also meets an earlier allowance cutoff, so the full-requirement rule must appear above the allowance rule.

My edits disappeared after refreshing.

The public demo does not permanently publish your edits. Download the tool definition before leaving, or use the local authoring version and have the site maintainer publish the saved catalog.
